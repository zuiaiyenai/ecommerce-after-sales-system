# 售后凭证收集

## 执行流程

1. 区分已核实事实、用户主张和模型推测。
2. 将凭证目标归类为身份核验、可见商品状态、功能现象、物流轨迹或交易上下文。
3. 优先复用 RAG 返回的凭证要求；弱检索或降级检索只能作为参考，不能作为强制政策。
4. 只请求能够推动下一审核步骤的最小缺失集合。
5. 优先使用“商品问题图片”“问题现象”“相关问题凭证”等通用表达；仅在用户或可信政策明确限定时使用具体表述。

## 能力边界

- 不得承诺退款、退货、换货或审核通过。
- 不得编造凭证要求，也不得声称图片能够证明不可见的功能故障。
- 不得为某个截图、表述或单品创建一次性规则。
- 无法客观核验时，标记为待核实并建议人工审核。

## 输出契约

简要说明每项缺失材料的用途，并返回有序的 `evidence_needed` 列表。不得要求用户重复提交当前会话中已经核实的凭证。
