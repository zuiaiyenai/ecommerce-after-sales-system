# 售后政策解释

## 执行流程

1. 说明每条可信命中支持的政策事实，并标明来源编码或标题。
2. 区分政策原文、已核实订单事实、用户陈述和 Agent 建议。
3. 存在 Java 绑定的会话或订单政策版本时，优先使用该版本。
4. 只解释与当前判断和凭证请求有关的条款。
5. 当检索模式、商家、版本、来源类型或分数不具备权威性时，明确说明不确定性。

## 可信规则

- 只有通过运行时政策 Gate 的严格 pgvector 结果才能支持自动审核。
- 关键词降级、本地降级、宽松过滤或低分命中可以用于解释，但不能授权自动通过。
- 不得把“未检索到政策”转换成模型推断的商家规则。
- 不得绕过 Java 对订单、工单、事务、幂等和权限的控制。

## 输出契约

生成简短的用户可读解释。引用和不确定性保留在结构化审计字段中；除非运营人员明确要求，不得暴露内部分数或原始检索 Trace。
